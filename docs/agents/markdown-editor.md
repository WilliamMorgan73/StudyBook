# MarkdownEditor (`frontend/src/components/MarkdownEditor.tsx`)

Obsidian-style *live preview* on `@uiw/react-codemirror` + `@codemirror/lang-markdown` (GFM extensions), used by `SubmodulePage`. Always editable, saves on blur. `sourceMode` (toggled in `SubmodulePage`'s header) just omits the live-preview extensions, leaving plain markdown.

## How live preview works

A `ViewPlugin` walks the Lezer syntax tree on every doc/selection change. Formatting marks (`MARK_NODES`: `HeaderMark`, `EmphasisMark`, `CodeMark`, `StrikethroughMark`, `QuoteMark`) are hidden with `Decoration.replace` on every line **except the cursor's line**; the surrounding node is styled unconditionally with `Decoration.mark`/`Decoration.line`. Every widget below follows the same cursor-line exemption. `basicSetup`'s `syntaxHighlighting` is off (its colors clash with the monochrome theme) in favor of hand-picked classes.

- `HeaderMark`/`QuoteMark` hiding extends through the trailing space too (`MARK_NODES_CONSUME_TRAILING_SPACE` / `skipTrailingSpace`), else "# Heading" renders as " Heading".
- `HorizontalRule` and `Image` become `HorizontalRuleWidget` / `ImageWidget`. On the cursor line an image (and an image/PDF/video `![[embed]]`) keeps rendering, as a widget after the source rather than replacing it: swapping a tall image for one line of text collapsed the page under the cursor as you arrowed onto it.
- **Lists**: a bullet `ListMark` becomes `BulletWidget`; an ordered one is just muted (`cm-list-number`). In a GFM `Task` (`ListItem > Task > TaskMarker`) the `ListMark` and its space hide and the `TaskMarker` becomes `CheckboxWidget` (`markdown-editor/listWidgets.ts`, styled after `ui/checkbox.tsx`); checked items get `cm-task-done`. The checkbox toggles on `mousedown` with `preventDefault` (so the cursor doesn't land on the line and expose `[ ]`), dispatching with the `TOGGLE_TASK_EVENT` user event (see **Saving** below).
- **Links**: an inline `Link` with a `URL` child (`[text](url)`) hides `[` and `](url)` and marks the text `cm-link` with `data-href`. `[[Wikilinks]]` also parse as `Link` but have no `URL`, so they're skipped here.
- `FencedCode`/`CodeBlock` get a per-line box (`cm-codeblock`, `-start`/`-end` for rounding) that stays visible regardless of cursor; only the fences hide. `CodeInfo` gets a muted `cm-code-lang` style.
- **Callouts** (`> [!type] Title`, Obsidian syntax; types in `CALLOUT_TYPES`, unknown → `note`): the `Blockquote` branch checks the first line with `parseCalloutHeader` (`lib/markdownBlocks.ts`). A callout gets `cm-callout callout-<type>` line classes (plus `-start`/`-end`/`-title`) instead of `cm-quote`, so it stays live-editable with no block widget; off the cursor line `[!type] ` becomes `CalloutMarkerWidget` (icon, plus the type's label if untitled). Accent colors are `--callout-<type>` in `index.css`, where `.callout-<type>` sets `--callout-accent` for both the editor and `MarkdownView`'s `.callout`.
- **Side box** (`:::columns` / main / `:::side Title` / side / `:::`): line-scanned by `findColumnsBlocks` (needs both `:::side` and the closing `:::`, else it stays raw; no nesting) into `columnsDecorations`, a block `ColumnsWidget` rendering `ColumnsBlockView` (two `MarkdownView`s in a container-query grid that stacks when narrow). `ignoreEvent() → false` so a click puts the cursor in the block and reveals the source.
- **React inside widgets** (`markdown-editor/blockWidgets.tsx`): `mountReact` does `createRoot` in `toDOM` and `unmountReact` defers `root.unmount()` to a microtask in `destroy` (CodeMirror can destroy widgets mid-React-render). Block widgets also get a `ResizeObserver` → `view.requestMeasure()`, since their content renders and resizes (images, KaTeX) after `toDOM`. `.cm-content` is `white-space: pre-wrap`, so `.cm-columns` resets it to `normal`, or react-markdown's `"\n"` text nodes between elements render as blank lines.
- **Embeds** (`![[name]]`, optional ignored `|size`): `findEmbeds`/`resolveEmbed` (`lib/markdownBlocks.ts`; exact filename first, then case-insensitive, first wins, so duplicate filenames all resolve to the first) against `attachmentsFacet` (`markdown-editor/embedWidgets.ts`), which `MarkdownEditor` fills from its `attachments` prop. `embedDecorations` is a `StateField` that recomputes every transaction, including the reconfigure bringing new Attachments. An image becomes `ImageWidget`; a PDF/video/audio alone on its line becomes a block `MediaEmbedWidget` (PDF in an `<iframe>` with `#view=FitH&navpanes=0`, i.e. the browser's viewer); anything else, or inline, a `FileChipWidget` link, or "Missing attachment" if unresolved. `addWikilinkDecorations` skips `[[...]]` preceded by `!`. `MarkdownView` doesn't resolve `![[...]]` (it has no Attachments), so inside a side box use `![](url)` images.
- **Multi-line widgets live in their own `StateField`s, not the `ViewPlugin`**: CodeMirror forbids a `ViewPlugin` from providing block decorations or ones that replace line breaks. Hence `tableDecorations` (GFM `Table` → `TableWidget`), `mathBlockDecorations` (`$$...$$`), `columnsDecorations` and `embedDecorations`.
- `@lezer/common`'s `SyntaxNode` type isn't resolvable under this pnpm layout, so node shapes are typed locally (`WalkableNode`, `TableRowSource`).

### Regex-scanned syntax

Wikilinks, math and `==highlight==` aren't CommonMark/GFM, so there's no tree node; they're found by regex per visible range, skipping anything inside code (`isInsideCode`, `markdown-editor/syntax.ts`).

- **Wikilinks** (`WIKILINK_PATTERN`, `addWikilinkDecorations`): delimiters hide on unfocused lines. Cmd/Ctrl+click (`linkClickHandler`, which also opens `data-href` web links, `http(s):`/`mailto:` only) calls `onNavigateWikilink` → `resolveWikilink` → `GET /submodules/resolve`; unresolved is a silent no-op. `SubmodulePage.handleNavigateWikilink` must `await saveContent()` before `navigate()`: the click never blurs the editor, so unsaved edits would be lost on unmount.
- **Highlight** (`HIGHLIGHT_PATTERN`/`findHighlights` in `lib/markdownBlocks.ts`): `cm-highlight` with delimiters hidden; needs non-whitespace inside both `==` so `a == b` stays text. Color is `--note-highlight` in `index.css`.
- **Math** (`BLOCK_MATH_PATTERN`, `INLINE_MATH_PATTERN`): rendered with `katex.render` into the widget node (no HTML string to sanitize); falls back to plain text on parse error. Inline matches inside a block-math span are skipped (`findBlockMathRanges`) so `$$x$$` isn't also read as inline. Inline requires non-whitespace just inside both `$` so "$5 and $10" stays text.

## Folding: headings and embeds

`markdown-editor/folding.ts`, included in both live and source mode.

- **Headings** use lang-markdown's own fold service (`headerIndent`), which folds from the end of the heading line to the next heading of the same or higher level, with `codeFolding({ placeholderText: '…' })` and `.cm-foldPlaceholder` styling. A `ViewPlugin` puts a `FoldChevronWidget` at the start of each foldable heading line, absolutely positioned in the gutter (`.cm-heading` is `position: relative`), shown on hover and always when folded. It toggles on `mousedown` with `preventDefault` through `EditorView.domEventHandlers` (`ignoreEvent() → false`), so the cursor doesn't move onto the heading. Keys come from `basicSetup`'s `foldKeymap`: Ctrl-Shift-[ / ] to fold or unfold at the cursor, Ctrl-Alt-[ / ] for all (Cmd-Alt on Mac).
- **Embeds**: a `collapsedEmbeds` `StateField` holds Attachment URLs, flipped by `toggleEmbedEffect`. `MediaEmbedWidget` takes `collapsed` (part of `eq`), renders just its header when collapsed, and its header's toggle button dispatches the effect from its own `mousedown` listener. A widget's events never reach `domEventHandlers` unless `ignoreEvent` returns false, which an iframe embed shouldn't do. Images and file chips have no header, so they don't collapse.
- **Persistence**: given `foldStorageKey` (`submodule:<id>`, `assignment:<id>`), folds are saved to `localStorage` (`studybook:folds:<key>`) as `{ headings: <line text>[], embeds: <url>[] }` whenever they change, and restored in `onCreateEditor` (after `ensureSyntaxTree`). Headings match by exact line text, so renaming one forgets its fold. Pages remount the editor per note (`key={id}`), which is what makes restoring at creation enough.

## Saving

Notes save on blur (`onBlur`), but edits that aren't typing can happen while the editor is unfocused, so no blur follows: a checklist tick (`TOGGLE_TASK_EVENT`), an inserted block or picked attachment (`INSERT_BLOCK_EVENT`), or a finished upload (`UPLOAD_EVENT`). `onUpdate` calls `onCommit` for transactions with those user events (`COMMIT_USER_EVENTS`). `SubmodulePage.saveContent` reads `contentRef`, not `content`, because `onCommit` runs before React re-renders with the new value (react-codemirror's own `onChange` listener runs before `onUpdate`, so the ref is already current).

## Uploads: paste, drop and pickers

`MarkdownEditor`'s `onUploadFile` (from `SubmodulePage.uploadToNote`: upload, then await the Submodule refetch so the new Attachment resolves straight away) enables:

- **Paste/drop** (`markdown-editor/fileDrop.ts`): files in a paste or drop upload as Attachments. Each gets a placeholder line (`[Uploading name… #n]`) at the cursor/drop point, replaced by `attachmentMarkdown` (`![](url)` for images, unique even for repeat names; `![[filename]]` otherwise) by searching for its unique text, so edits meanwhile don't matter. Removed on failure (error shown as a toast) or if deleted meanwhile; skipped if the view is gone (navigated away). A browser's generic clipboard `image.png` is renamed `Pasted image <date> <time>.png` (`pastedImageName`). No files, or no `onUploadFile`, returns false so CodeMirror handles the event.
- **Pickers**: `/image` and `/embed` open `AttachmentPickerDialog` (images only, or every Attachment, plus Upload…), inserting through `insertBlock`.
- **Side-box image** in `InsertBlockDialog`: an existing image Attachment or an upload, placed first in the box.

Dialogs are opened from the `/` menu by `openDialogEffect` (a `StateEffect<EditorDialog>`, `'block' | 'image' | 'file'`) picked up in `onUpdate`.

## Block builder

`InsertBlockDialog` (`markdown-editor/`) builds a callout or side box with a live preview, using `buildCalloutMarkdown`/`buildColumnsMarkdown`. `MarkdownEditor` owns it: the `/` menu's "Block…" command dispatches `openBlockDialogEffect`, picked up in `onUpdate`, and `SubmodulePage`'s **Insert** button calls `openBlockDialog()` on the `MarkdownEditorHandle` ref. The block goes at the cursor when opened (the end of the note if it was never focused) on its own lines, blank line above, with the cursor left on a fresh line below so it renders straight away; the dialog's `onCloseAutoFocus` refocuses the editor instead of Radix's trigger.

## Gotchas

- **No vertical margins on lines or widgets.** CodeMirror measures each line and block widget by its border box, so a vertical margin is height its height map never sees; every one pushes where clicks and Up/Down land further down for everything below it (a note with five code blocks and two callouts resolved clicks four lines too low). The theme lives in `markdown-editor/theme.ts` (`EDITOR_THEME_SPEC`) and `theme.test.tsx` rejects vertical margins there and on `ColumnsBlockView`'s root. Space things with padding, a transparent border plus `backgroundClip: 'padding-box'` (code blocks and callouts; their vertical corner radius grows by the border, and the callout stripe is an inset `box-shadow` so it stays out of the gap), or a wrapper element (`cm-image-wrap`, `cm-table-wrap`, `cm-embed-wrap`).

- **Focus is hand-tracked**, because `view.hasFocus`/`.cm-focused` never toggled reliably here (hidden cursor, line 1 marks stuck visible). A `focusedField` `StateField<boolean>` is set by a `StateEffect` from React's `onFocus`/`onBlur`, debounced one tick (a click can fire several focus/blur events, and each dispatch rebuilds decorations). An `editorAttributes` facet adds `cm-live-focused`; `buildDecorations` reads `state.field(focusedField, false)`.
- **Theme rules keyed on a class of the editor root need the `&` prefix** (`'&.cm-live-focused .cm-cursor'`). A bare selector gets an ancestor scope prepended by `EditorView.theme()` and can never match.
- **Never build `EditorView.theme()` per render.** Each new theme object mounts a permanent CSS rule that CodeMirror never removes, so stale rules compete in the cascade. Dynamic values (`fontSize`, `tableAlign` from `AppSettings`) go through `buildDynamicAttributes` as CSS custom properties (`--note-font-size`, `--note-table-margin-x`) in an inline `style` via `EditorView.editorAttributes`, read by the static `editorTheme` with `var(..., fallback)`.
- **The editor grows and the page scrolls.** `.cm-scroller` uses `flex: '1 1 auto'` plus `overflow: 'visible'`. With `flex-basis: 0` the editor resolved to exactly `minHeight` (70vh) and scrolled internally.
- Cursor blink is off (`drawSelection({ cursorBlinkRate: 0 })`; the facet takes `Math.min`, so 0 wins): on a blank line a blinking cursor reads as missing.
- Spellcheck goes through `EditorView.contentAttributes` (the wrapper has no prop reaching `.cm-content`), turned back off per `InlineCode` node and per code-block line.

## Keybinds, the `/` menu and slash commands

- **`/` menu** (`markdown-editor/slashMenu.ts`): every command's `id` is one typeable word (`heading2`, `bulletlist`, `tipcallout`, `sidebox`), shown in the menu as its hint (`detail` defaults to `/id`), since the menu closes on a space. The label with its spaces dropped also matches (`/numberedlist`). Results rank id/label-prefix matches over label-word and keyword-only ones (`matchRank`), so `/block` puts Block… before Quote. a `@codemirror/autocomplete` source (`override`, so no language completions; `basicSetup.autocompletion` stays off). Opens on `/` at line start or after whitespace (so `and/or` doesn't), skips code. The command set, filtering and insert planning are pure functions in `lib/markdownBlocks.ts` (`SLASH_COMMANDS`, `filterSlashCommands`, `planSlashInsert`, unit tested). `filter: false` because `/table4x2` yields an option whose label doesn't contain the query. A `block` command typed after text goes on a new line; typed on a bare list/checklist/quote marker line (an Enter-continued `- [ ] `) it replaces the marker. The popup is restyled in `editorTheme` to match Radix popovers. It opens ~100 ms after typing and ignores Enter for 75 ms after opening, so fast synthetic input in browser automation can miss it.

- `buildFormattingKeymap(keybinds)` (`Prec.highest`) maps `AppSettings.keybind_*` (fallback `DEFAULT_KEYBINDS` in `lib/keybinds.ts`: `Mod-b`/`Mod-i`/`Mod-e`/`Mod-Shift-k`) to `toggleWrapCommand`. Rebuilt per render since bindings are user-configurable; `keymap.of()` has no stylesheet cost. Mod-K is never the wikilink default: browsers eat it.
- Backslash commands (`\bold`, `\link`, `\code`, `\codeblock`, `\image`, `\table<N>x<M>`) expand on Space/Enter via `runSlashCommand` in the module-level `slashCommandKeymap` (`Prec.highest`). It matches `SLASH_TRIGGER_PATTERN` before an empty cursor, skips code, and deletes+inserts in one dispatch (one undo step). Simple ones are table-driven (`SIMPLE_SLASH_COMMANDS`, `{before, after}`). `\table` (`TABLE_SLASH_PATTERN`, max `MAX_TABLE_DIMENSION` = 12) builds N columns × M data rows plus header via `buildTableMarkdown` (`lib/markdownBlocks.ts`), selecting `"Header 1"`. Note `\link` inserts a wikilink while `/` menu "Web link" inserts `[text](url)`.
- Empty table cells must contain `EMPTY_CELL` (U+200B): Lezer emits no `TableCell` for an all-whitespace cell, so rows silently lose their cells. U+200B survives `.trim()`.
