# Backend (`backend/app/`)

## Layout

- `models/`: SQLAlchemy 2.0 (`Mapped`/`mapped_column`). Relationships use bare string forward refs (`Mapped["Module"]`) rather than cross-imports, to avoid circular imports. `models/__init__.py` is the one place that imports every model module, so always import via `app.models` before touching `Base.metadata` or querying, or string refs won't resolve.
- `schemas/`: Pydantic request/response models, separate from the ORM models. `ModuleDetail` (`schemas/module.py`) is the module page's aggregate payload: lectures, assignments, submodules, flashcards, related modules, plus computed fields (`current_grade`, `next_lecture_at`, progress) that aren't DB columns.
- `crud/`: plain functions, no generic repository layer.
  - `grades.py::compute_current_grade`: weighted average over graded assignments (by `weight_percent`, else unweighted mean). Computed on read.
  - `grades.py::compute_completion_progress`: `completed_fraction` sums `weight_percent` of `submitted`/`graded` assignments out of the module's full 100%; `achieved_fraction` additionally scales each graded one by `grade_earned/grade_max`. `assignment_progress` (graded/in_progress/not_started counts) is separate, for textual breakdowns.
  - `spaced_repetition.py::apply_review`: SM-2; mutates a `Flashcard`'s `ease_factor`/`interval_days`/`repetitions`/`due_at` in place from a 0–5 quality rating.
  - `busy_time.py`: pure busy-time expansion. `expand_personal_events(events, start, end)` turns `PersonalEvent` weekly rules into `BusyOccurrence`s overlapping `[start, end)` (unclipped, sorted); `busy_intervals` merges and clips them into plain `(start, end)` intervals for the revision planner.
  - `calendar_feeds.py`: ICS calendar feeds. Pure: `parse_feed(ics_text, window_start, window_end)` expands recurrences with `recurring_ical_events` (RRULE/RDATE/EXDATE/RECURRENCE-ID), skips `TRANSP:TRANSPARENT` and `STATUS:CANCELLED`, converts aware times to the server's local naive time (floating times kept), names untitled events "Busy", drops zero-length timed events, and splits all-day events into one midnight-to-midnight `FeedOccurrence` per day (`all_day=True`), since the calendar places events on their start day; unparseable text raises `FeedParseError`. `normalize_feed_url` turns `webcal://` into `https://` and accepts only http(s). Side effects: `refresh_feed(feed, fetch=None)` fetches via `fetch_ics` (httpx, 10s; looked up per call so tests monkeypatch `calendar_feeds.fetch_ics`), caches the window `WINDOW_PAST` (30 days) to `WINDOW_FUTURE` (365 days) around now by replacing `feed.events`, sets `last_synced_at` (UTC) and clears `last_error`; any fetch/parse failure keeps the cached events and `last_synced_at` and sets a URL-free `last_error` instead of raising. `refresh_stale_feeds` refreshes enabled feeds unsynced for `STALE_AFTER` (1h). `feed_events_between(db, start, end, include_all_day=)` reads enabled feeds' cached events. Callers commit.
  - `spaced_repetition.py::review_card`: `apply_review` plus a new `FlashcardReview` history row (returned for the caller to `db.add`). `POST /flashcards/{id}/review` goes through it, so every review is logged.
- `api/routes/`: one router per resource, all included in `main.py`.
  - `calendar.py` is read-only and table-less: merges `Lecture` and `Assignment` due dates and expanded `PersonalEvent` occurrences into sorted `CalendarEvent`s. Lectures and exams (`kind="exam"`) carry `ends_at` from `duration_minutes`, and `location`; both are `None` for coursework (`kind="assignment_due"`). Busy time (`kind="busy"`) has `module_id`/`url` `None`. From a PersonalEvent, its `id` is the PersonalEvent's, repeated on every occurrence; from a calendar feed, `id` is the `CalendarFeedEvent`'s and `feed_id`, `color` and `all_day` are set (enabled feeds only). `GET /calendar` never fetches feeds.
  - `calendar_feeds.py`: CRUD plus `POST /calendar-feeds/{id}/refresh` (always 200; a failure shows as `last_error`) and `POST /calendar-feeds/refresh-stale` (`{refreshed}`, the Overview calls it on view). `_validate` (name, http(s)/webcal URL, `#rrggbb` colour) runs on the merged row. Create syncs straight away (a failed first sync still saves); a PATCH that changes the URL drops the old events and resyncs. `CalendarFeedRead.event_count` counts cached events. Never logs or echoes the URL in errors.
  - `personal_events.py`: CRUD. `_validate` (title, ≥1 weekday in 0–6, start ≠ end, `valid_until ≥ valid_from`) runs on the merged row, so PATCHes are checked too.
  - `quick_todos.py` / `quick_note.py` back the to-do lists and the Overview notepad, unrelated to per-assignment `AssignmentTodo`/`notes_markdown`. A `QuickTodo` with `module_id` null is General; with one, it's that module's own list (deleted with the module), and `GET /quick-todos?module_id=` lists just those. A module's own notepad is `Module.notes`.
- `core/config.py`: `pydantic-settings` `Settings` from `.env` (not committed). `core/database.py`: `Base`, `engine`, `get_db` dependency.

## Data model

`Module` (a course) is the root. `Lecture`, `Assignment`, `Submodule` (a topic with one `content_markdown` body, plus an optional AI `summary_markdown`/`summary_source_hash`) and `Flashcard` belong to a `Module`; a `Flashcard` optionally also belongs to a `Submodule`. `Flashcard.source` is `manual` (default) or `ai` (generated, then accepted in the review dialog). `FlashcardReview` is an append-only log of every rating (`quality`, `reviewed_at`), cascade-deleted with its card; the revision planner's weakness scoring will read it. `ModuleLink` stores "related modules" as two directed rows, one per direction.

`Assignment`: `weight_percent` is required, and a module's weights are capped at 100% in `api/routes/assignments.py` (not a DB constraint). It also has `notes_markdown`, ordered `todos` (`AssignmentTodo`) and `attachments`. Status `in_progress` is a valid enum value the UI no longer sets. `kind` is `coursework` (default) or `exam`; exams use `due_at` as the exam start and add nullable `duration_minutes`/`location`, but are otherwise ordinary graded Assignments (weight cap, grade and progress treat them the same). `covered_submodules` (join table `assignment_submodules`, cascade on both sides) lists the Submodules an Assignment covers; ids must belong to the Assignment's own Module, and on create an omitted list defaults to every Submodule for an exam and none for coursework. The revision planner will read exams' covered Submodules.

`PersonalEvent` (busy time: work shifts, training) stores a weekly rule, not one row per occurrence (unlike `Lecture`): `weekdays` (Postgres int array, 0 = Monday, Python `weekday()` numbering), naive `start_time`/`end_time` (an end before the start runs past midnight), inclusive `valid_from` and nullable `valid_until` (open-ended). It's expanded on read by `crud/busy_time.py`. Not tied to any Module.

`CalendarFeed` (a subscribed ICS address such as a Google Calendar secret URL; `name`, `url`, `color`, `enabled`, `last_synced_at` (UTC, last *successful* sync), `last_error`) caches its parsed events as `CalendarFeedEvent` rows (`title`, local naive `starts_at`/`ends_at`, `all_day`; cascade-deleted with the feed via the DB FK, `passive_deletes`). Rows are replaced wholesale on each successful refresh, so a failed fetch leaves the last good copy. No OAuth, no background jobs: feeds refresh on create, on URL change, on manual Refresh, when the Overview calendar is viewed and they're over an hour old, and (unconditionally) when a revision plan is made or replanned.

Datetimes are naive. Student-entered ones (lecture times, due dates, revision sessions) are local wall-clock time, written by the frontend's `toNaiveDateTime`; compare them against `core/clock.py::local_now()`, never `datetime.now(UTC)`. Server-generated ones (DB `now()` defaults, flashcard scheduling) are UTC.

`AppSettings` and `QuickNote` are single-row get-or-create tables (`id=1`), kept separate because one is configuration and the other user content. `AppSettings` fields are flat scalar columns with Python defaults, including the four `keybind_*` columns, each a raw CodeMirror keymap string (`"Mod-b"`, `"Mod-Shift-k"`). The exception is `dashboard_layout`, a nullable JSON list of `{i, x, y, w, h}` Overview grid items (`schemas/dashboard_layout.py::DashboardLayoutItem` checks the shape and the 12-column bound; widget ids belong to the frontend and aren't validated). `Module.dashboard_layout` is the same shape for that module's page; `Module.banner` is the module page banner's config (`schemas/module.py::ModuleBanner`: stat ids, ring, tint, size; null = frontend default). `QuickTodo` is a plain multi-row table.

### Attachments

`Attachment` is polymorphic by construction: `submodule_id` and `assignment_id` are both nullable and exactly one is set, because the only writers are the two upload endpoints (`POST /submodules/{id}/attachments`, `POST /assignments/{id}/attachments`) via `crud/attachments.py::store_upload`. Files go to `backend/uploads/{submodules,assignments}/<id>/<uuid>` (namespaced so equal ids can't collide); `file_path` is the disk path, `url` is a computed property served by the `/uploads` static mount. `DELETE /attachments/{id}` removes row and file. `kind` comes from the extension (`_EXTENSION_KIND`): png/jpg/jpeg/gif/webp are `image` (what note embeds and pasted images use); `.svg` deliberately stays `other`, since an SVG served from our own origin could run script. A file goes with its row however the row goes (deleting the Attachment, or a Submodule/Assignment/Module cascading to it): session hooks in `models/attachment.py` collect deleted Attachments' paths on flush and call `crud/attachments.py::remove_stored_file` only after commit (a rollback keeps the files), which also drops the emptied `uploads/<kind>/<id>/` folder and never touches anything outside the upload dir. Bulk `query.delete()` would bypass the ORM and orphan files, so don't use it on Attachments or their parents.

Text extraction lives in `crud/attachment_text.py`, the one entry point AI features use for an Attachment's text: `get_extracted_text(attachment, convert=...)` converts PDF/PPTX locally with `markitdown` on first call, caches it in the deferred `extracted_markdown` column (caller commits), and returns `ExtractedText(markdown, near_empty)`. `near_empty` (fewer than `NEAR_EMPTY_MIN_CHARS` letters/digits) is PDF-only and computed on read, not stored. Other kinds, and legacy `.ppt` filed under `pptx`, raise `AttachmentNotExtractableError`; a failed conversion raises `AttachmentExtractionFailedError` and isn't cached. `GET /attachments/{id}/extracted-text` wraps it (415 unsupported, 422 failed), and `AttachmentRead.text_extractable` tells the UI which rows get "View extracted text".

### Wikilinks

`[[Title]]` / `[[Title|Alias]]` links between submodules are resolved on demand, never stored, and are one-directional by design (a `SubmoduleLink` table plus backlinks panel was built and deliberately removed). `crud/submodule_links.py::resolve_wikilink` supports `"Module Title/Submodule Title"` disambiguation, else prefers a same-module match, else the first match anywhere. `GET /submodules/resolve?title=&module_id=` wraps it and 404s when unresolved. `GET /submodules` is a lightweight cross-module index (`SubmoduleIndexEntry`, optional `search`) for a future link picker.

### Revision planner

`RevisionSession` (an exam Assignment's planned revision block): `starts_at`, `duration_minutes`, `done`, nullable `guidance_markdown` (AI guidance, filled lazily by #13), and its Submodules via `revision_session_submodules` (cascade on both sides). Sessions cascade-delete with their exam.

- `crud/revision_planner.py` is pure and deterministic. `weakness_scores(reviews, submodule_ids, last_n=20)` gives each Submodule a 0–1 lapse rate (quality < 3) over its latest `last_n` reviews (via `review.flashcard.submodule_id`), smoothed towards `NEUTRAL_WEAKNESS` (0.5, exactly what a Submodule with no reviews gets) by `PRIOR_REVIEWS`. `weakest_cards(cards, limit)` ranks reviewed cards by recent lapse rate (reads `card.reviews`). `schedule_revision(exam_starts_at=, submodule_ids=, weakness=, start_date=, weekdays=, session_minutes=, blocked=, not_before=)` returns `list[ProposedSession]` or `NotEnoughTime` (with a readable `message`): at most one session per chosen weekday, the earliest 15-minute-aligned gap in 09:00–21:00 that avoids every `blocked` interval and ends by the exam. With at least as many sessions as Submodules each gets one session and the rest go by weakness (largest remainder), interleaved; with fewer, several Submodules share a session (one per 30 minutes of length), else `NotEnoughTime`.
- `crud/revision_plans.py` gathers inputs from the DB: `blocking_intervals(db, start, end, exam_id)` (every Lecture, busy time (personal events, and enabled feeds' timed events; all-day feed events never block), other exams and their sessions; no-duration lectures/exams block 60 min), `submodule_weakness(db, ids)`, and `plan_exam_revision(db, exam, start_date=, weekdays=, session_minutes=, weakness=, now=, kept=)`, which writes nothing (`kept` sessions are blocked, and their days get no new session); `save_plan` makes kept + proposed the exam's sessions and records the baseline; `exam_replan_signal(db, exam, now)`.
- Replanning is manual. `Assignment.revision_planned_at` (local naive) and `revision_planned_weakness` (JSON, `str(id)` → score) are the baseline, set on every plan/replan and cleared with the plan. Pure rules in `revision_planner.py`: `split_for_replan(sessions, now)` keeps done or already-started sessions and replaces the rest; `replan_signal(...)` reports missed sessions (not done, ended, started at/after `planned_at`) and `WeaknessShift`s (a covered Submodule's weakness moved by ≥ `WEAKNESS_SHIFT`, 0.2; Submodules missing from the snapshot never count). A plan saved before the baseline existed counts from its first session and never shifts.
- `api/routes/revision.py`: `POST /assignments/{id}/revision-plan` (exams with a date and covered Submodules only; 409 if a plan exists; 422 with `NotEnoughTime.message` as `detail`), `POST …/revision-plan/replan` (same body; 409 without a plan, 400 once the exam has started, 422 leaves the plan unchanged; returns the whole plan), `GET …/revision-plan/status` (`needs_replan`, `missed_session_ids`, `shifted_topics`; quiet without a plan or once the exam has started), `DELETE` of the plan path (clears the plan, done sessions included), `GET /revision-sessions?assignment_id=&module_id=&start=&end=`, `GET /revision-sessions/{id}` (the session view: `topics` with current weakness, `weakest_cards`) and `PATCH /revision-sessions/{id}` (`done`). The calendar feed includes sessions as `kind="revision"` with `done`, linking to the exam page's `?session=`.
- Endpoint tests (`tests/test_revision_endpoints.py`) run against in-memory SQLite with only the tables they need; `personal_events.weekdays` (a Postgres array) is compiled as JSON there and never written.

## AI service

Every AI call goes through `services/ai.py`'s `AIClient` protocol, implemented by `AnthropicAIClient` and `GeminiAIClient`: `ping()` (model lookup, no tokens; backs `POST /ai/test`), `complete(prompt, system=, max_tokens=, documents=) -> str`, and `complete_structured(prompt, schema, ..., documents=) -> schema instance` (Anthropic `messages.parse`; Gemini JSON mode with `response_json_schema`; a reply that doesn't fit the schema becomes `AIError("unknown")`). `documents` are `AIDocument(title, data)` raw PDFs, sent before the prompt (document blocks / inline parts). Gemini's thinking counts against its output limit, so `GeminiAIClient` adds `GEMINI_THINKING_ALLOWANCE` to `max_tokens`; a Gemini safety block becomes `AIError("refusal")`, and raw httpx connection errors (the SDK doesn't wrap them) become `network`. Feature functions take an `AIClient` parameter; routes get one from `api/deps.py::get_ai_client`, which reads AppSettings and calls `build_ai_client(model, anthropic_api_key=, gemini_api_key=)`, the only place an SDK client is constructed; the model's provider picks the client and key. SDK failures become `AIError(kind, message)` with a readable message; `main.py`'s handler returns them as `{"detail", "kind"}` (`not_configured` 409, `rate_limit` 429, `network`/`unavailable` 503, others 502). Tests use `FakeAIClient` (queued replies, recorded `requests`) or override `get_ai_client`; `tests/conftest.py` blanks both env keys for every test.

`AppSettings.anthropic_api_key` and `gemini_api_key` are write-only and both kept: `AppSettingsRead.from_row` reports `has_anthropic_api_key`/`has_gemini_api_key` (saved in the row), `ai_provider` (derived from `ai_model`) and `ai_enabled` (the selected provider has a key, saved or `ANTHROPIC_API_KEY`/`GEMINI_API_KEY` in `core/config.py`, saved wins). PATCH sets a key (trimmed), clears it with `null`/`""`, or leaves it alone when omitted. `ai_model` is validated against `services/ai_models.py::AI_MODELS`, the one model list (each with its `provider`), also served at `GET /ai/models`; there is no separate provider column. `provider_of(model)` also gives `pdf_tokens_per_page` for the raw-PDF estimate (Claude ~2,000, Gemini 560).

### Submodule source material (shared by every Submodule AI feature)

`services/submodule_source.py` decides what "this topic" means when sent to the AI, so flashcard generation and summaries (#8) send the same thing. `gather_submodule_source(submodule, raw_pdf_ids=, extract=, count_pages=)` takes the note plus every extractable Attachment's text via `get_extracted_text` (may convert and cache; caller commits; media skipped; failed extractions kept with `error` and left out) and returns a `SubmoduleSource`: `text_markdown()` (note and Attachments in `<note>`/`<attachment>` tags), `documents()` (the opted-in raw PDFs as `AIDocument`s), `estimated_tokens`/`large` (chars/4, `pdf_tokens_per_page` per raw-PDF page (the selected provider's, passed by `load_submodule_source`), `LARGE_REQUEST_TOKENS` threshold), `near_empty_attachments`, `is_empty`. A raw PDF is only sent for ids in `raw_pdf_ids`, which must be this Submodule's near-empty PDFs (else `RawPdfNotAllowedError`); it replaces that file's thin text.

`api/routes/submodule_ai.py` holds the Submodule AI endpoints. `load_submodule_source(db, submodule_id, raw_pdf_ids)` is the route-side wrapper (404, 422 on a bad raw-PDF id, commits new extraction caches); `GET /submodules/{id}/ai-source?raw_pdf_ids=` returns it as a `SubmoduleSourceEstimate` so the UI can show the size and raw-PDF opt-ins before running. Each AI action takes the same `raw_pdf_ids` and calls `load_submodule_source` itself.

Flashcard generation (`services/flashcard_generation.py`, `POST /submodules/{id}/flashcards/generate` with `{count, raw_pdf_ids}`): count 1–`MAX_CARD_COUNT` (30), default 10. Sends the material plus the Submodule's existing card fronts, asks for `CardProposals` structured output, and `clean_proposals` trims, drops blanks and duplicates (case/whitespace-insensitive, against existing fronts and within the reply) and cuts to `count`. Returns proposals only; accepted cards are created by the client through `POST /flashcards` with `source: "ai"`.

Summaries (`services/submodule_summary.py`, `POST /submodules/{id}/summary` with `{raw_pdf_ids}`): free-text `complete` call; stores `Submodule.summary_markdown` plus `summary_source_hash` = `source_hash(source)`, and returns the updated `SubmoduleDetail`. A failed call leaves the old summary. `source_hash` is a pure SHA-256 of the note and each extractable Attachment's text (failed extractions as `null`), deliberately ignoring the raw-PDF opt-in and the title. Single-Submodule endpoints (`GET`/`PATCH`/`POST /submodules`) return `SubmoduleDetail` (`SubmoduleRead` + `summary_markdown` + computed `summary_stale`); `ModuleDetail` keeps plain `SubmoduleRead` so it doesn't hash every Submodule. `summary_is_stale` re-gathers the source from cached extractions only (never converts), so an Attachment uploaded since and not yet converted counts as unreadable, which differs from its absence and flags the summary stale. Nothing regenerates automatically.

## Alembic

`alembic/env.py` imports `app.models` and reads the URL from `settings.database_url`, not `alembic.ini`. Run migrations from `backend/` with `uv run alembic ...`.
